弹幕算法笔记：用极坐标画一朵「花」

2026-07-15 技术 959 字 约 3 分钟

弹幕看起来像是把许多子弹随意撒上屏幕，真正写起来却更像在纸上作图：先确定一条轨迹，再决定沿轨迹放多少个点。只要把“位置”与“时间”分开思考，圆环、花瓣和螺旋就都能从同一套极坐标公式里长出来。

符卡宣言：「算符『一圈分成多少份』」——美感往往来自规律，以及恰到好处的偏离。

极坐标的起手式

平面坐标用 x、y 描述位置；极坐标则用半径 r 和角度 θ。二者的转换只有两行：

const x = cx + Math.cos(theta) * radius;
const y = cy + Math.sin(theta) * radius;

若在同一帧把角度均分成若干份，再给每颗子弹相同速度，就得到向外扩散的圆环。为了避免每次出现完全相同的缝隙，可以给整圈加一个随时间变化的起始角。玩家感受到的是“弹幕在转”，程序里其实只是下一轮发射时多加了一个偏移量。

让圆环长出花瓣

把固定半径换成随角度起伏的半径，圆就会变成花。常用的玫瑰线写作 r = a × cos(kθ)：参数 k 控制花瓣数量，a 控制整朵花的尺寸。实际游戏里不必真的把子弹放在曲线上；可以把曲线点当作发射方向，再让子弹沿该方向移动。

for (let i = 0; i < count; i++) {
  const theta = i / count * Math.PI * 2;
  const radius = 1 + 0.35 * Math.cos(theta * petals);
  spawn(theta, speed * radius);
}

这里的 radius 被用来调节速度，快弹与慢弹交错后，原本规整的圆环在飞行中逐渐拉开，花瓣轮廓也就显出来了。参数变化最好缓慢：一次只改花瓣数、速度或旋转方向中的一个，玩家才能读懂图案。

螺旋为什么不会挤成一团

连续发射时，每帧把角度增加一个固定值即可形成螺旋。若增量与一整圈存在简单整数比，子弹会排成明显的辐条；改用黄金角约 2.39996 弧度，相邻发射方向不容易重合，画面会像向日葵种子一样均匀铺开。

黄金角不是必选答案。弹幕需要留出可读的安全通道时，反而应该选一个容易形成辐条的角度，再通过周期性加速或正反旋转制造节奏。数学提供秩序，关卡设计决定这种秩序对玩家是否公平。

让上千颗子弹保持轻盈

每颗子弹只保存位置、速度、尺寸、颜色与存活时间；离开屏幕边界后立即移除。绘制时复用同一个 Canvas，不为子弹创建 DOM 节点。设备像素比最多取 2，移动端降低同时存在的数量，页面隐藏时暂停动画。最后还要尊重 prefers-reduced-motion：对不需要动态效果的访客，最好的优化就是不启动引擎。

调试时先画单色小圆点，确认轨迹正确后再加外圈、辉光和渐变。这样能区分“算法不对”和“样式太重”两类问题，也能更快找到真正消耗帧率的地方。
